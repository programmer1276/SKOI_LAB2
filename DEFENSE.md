# Шпаргалка для защиты ЛР2

## Что показать за 3–5 минут

1. Открыть `README.md` и коротко назвать цель.
2. Показать схему алгоритма: ROI → ORB → BFMatcher → ratio test → RANSAC → гомография → рамка.
3. Открыть `tracker.py`: инициализацию ORB, `knnMatch`, `findHomography`, `perspectiveTransform`.
4. Запустить `python run_all.py` и объяснить таблицу метрик.
5. Открыть хотя бы три файла `outputs/*_tracked.mp4`: перенос, поворот/масштаб, перекрытие.
6. Показать своё `outputs/my_video_tracked.mp4`.

## Готовый короткий рассказ

«На первом кадре пользователь задаёт прямоугольную область объекта. Я ищу ORB-ключевые точки только внутри неё и запоминаю их бинарные дескрипторы. На каждом следующем кадре ORB работает уже по всему изображению. Для каждого эталонного дескриптора BFMatcher по расстоянию Хэмминга находит два ближайших, после чего ratio test удаляет неоднозначные совпадения. По оставшимся парам RANSAC оценивает гомографию — матрицу перспективного преобразования. Этой матрицей я переношу четыре угла исходной рамки. Если согласованных с моделью точек меньше семи или геометрия рамки нереалистична, объект помечается как LOST. На тестах я сравниваю рамку с эталоном через IoU».

## Возможные вопросы преподавателя

**Почему выбран ORB?**  
Он быстрый, свободный, поддерживает поворот и масштаб за счёт ориентации точки и пирамиды, а бинарный дескриптор быстро сравнивается расстоянием Хэмминга.

**Что такое ключевая точка?**  
Повторно обнаруживаемая локальная особенность, обычно угол или контрастная текстурная область. Дескриптор численно описывает её окрестность.

**Зачем два ближайших совпадения?**  
Чтобы проверить уникальность лучшего кандидата. Если первое и второе расстояния близки, соответствие ненадёжно.

**Почему для гомографии нужно минимум четыре пары?**  
У гомографии восемь независимых параметров; одна пара точек даёт два уравнения, поэтому нужны минимум четыре пары.

**Зачем RANSAC?**  
Обычная оценка испортится из-за ложных совпадений. RANSAC ищет модель, которую подтверждает максимальное число согласованных точек, и помечает остальные выбросами.

**Что такое inlier?**  
Соответствие, положение которого согласуется с найденной гомографией в пределах порога ошибки.

**Почему рамка иногда наклонная?**  
Переносятся все четыре угла перспективным преобразованием. Это точнее обычного осевого прямоугольника при повороте объекта.

**Что означает IoU?**  
Отношение площади пересечения предсказанной и эталонной рамок к площади их объединения. Чем ближе к 1, тем лучше.

**Когда алгоритм сломается?**  
На однотонном объекте, при полном длительном перекрытии, сильном размытии, выходе из кадра или множестве одинаковых узоров.

**Чем это отличается от оптического потока?**  
Оптический поток переносит локальные точки между соседними кадрами и может накапливать ошибку. Здесь каждый кадр напрямую сопоставляется с исходным описанием объекта, поэтому дрейф меньше, но требуется сохранение внешнего вида.

**Почему скорость выше FPS видео?**  
`processing_fps` показывает вычислительную скорость без ожидания реального времени. Видео имеет 30 FPS, а обработка одного кадра занимает существенно меньше 1/30 секунды.

## Команды на защите

```bash
source .venv/bin/activate
python run_all.py
python tracker.py data/my_video.mp4 --show \
  --output outputs/my_video_tracked.mp4 \
  --metrics outputs/my_video_metrics.json
```

Если нужно быстро показать один уже готовый прогон без окна выбора ROI:

```bash
python tracker.py data/02_scale_rotation.mp4 \
  --bbox 257,138,127,85 \
  --output outputs/demo.mp4
```
